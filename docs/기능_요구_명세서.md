# AI 소비 패턴 분석 및 절약 코치 — 기능 요구 명세서

본 문서는 서비스의 기능·비기능 요구사항, 시스템 구조, AI 활용 방식과 구현 현황을 정의한다. 우선순위는 Must(제출 필수), Should(권장), Could(여유 시)로 구분하며, Must 16개를 제출 기준으로 한다. 코드 위치의 줄 번호는 2026-11-20 제출본(`main`) 기준이다.

- 배포 URL: https://final-project-frontend-seven-beta.vercel.app (로그인 없이 "로그인 없이 체험하기"로 바로 사용 가능)

## 2. 비기능 요구사항

실제 카드·통장 내역을 다루므로 데이터 분리와 개인정보 보호, 그리고 AI가 만든 숫자의 정확성을 가장 중요하게 본다.

| ID | 항목 | 요구사항 | 구현 방식 |
| --- | --- | --- | --- |
| NFR-01 | 데이터 분리 | 사용자는 본인 데이터만 읽고 쓸 수 있다. | 모든 API가 Firebase ID 토큰을 검증하고 `users/{uid}/…` 경로만 접근한다. 다른 사용자의 문서 ID로 요청하면 404를 돌려준다. |
| NFR-02 | 개인정보 보호 | 동의 없이 수집·처리하지 않고, 필요한 최소한만 저장한다. | 동의 전 요청은 403. 원본 이미지·카드번호·계좌번호는 저장하지 않고 추출된 거래만 저장한다. 전체 삭제를 제공한다. |
| NFR-03 | AI 생성 표시 | AI가 만든 내용임을 사용자에게 알린다. | 채팅 답변마다 "AI 생성 답변 · 참고용", 인식 확인 표에 "AI 생성 결과"를 표시한다. |
| NFR-04 | 정확성 | 금액·합계·비율·날짜는 코드가 계산하고, AI는 근거 없는 숫자를 만들지 않는다. | 요약·목표·날짜·중복은 코드 규칙으로 처리한다. Agent는 도구 결과에 있는 숫자만 쓰고, 조회 근거를 화면에 공개한다. 평가 3회에서 지어낸 숫자는 0건이었다. |
| NFR-05 | 사람 확인 | AI 인식 결과는 사용자 확인 없이 저장하지 않는다. | 인식(저장 안 함) → 확인 표 → 일괄 저장의 2단계 API로 나눈다. |
| NFR-06 | AI 행동 제한 | AI는 사용자 데이터를 직접 바꾸지 않는다. | Agent 도구는 모두 읽기 전용이다. 사용자 ID는 모델이 아니라 서버가 넣는다. 목표 변경은 제안 카드로만 만들고, 사용자가 [적용]해야 저장된다. |
| NFR-07 | 비용 통제 | 사용량이 늘어도 비용이 통제된다. | 하루 채팅 50회·이미지 30장 제한(AI 호출이 실패하면 차감한 1회를 되돌림), 소비 알림 카드는 AI 미사용, 답변 500 토큰, Agent 최대 5단계·단계당 도구 4개, 브라우저 이미지 축소, 요약 캐시, OpenAI 월 사용 한도를 둔다. |
| NFR-08 | 응답 속도 | 채팅은 10초, 이미지 1장은 20초 안에 응답한다(서버 깨우는 시간 제외). | 이미지를 1장씩 처리하며 진행 상황을 표시하고, 타임아웃은 90초로 둔다. |
| NFR-09 | 가용성 | 무료 서버가 잠들어 있어도 접속이 깨지지 않는다. | 접속 시 `/health`를 호출하고, 깨우는 중 배너를 띄우며, 실패 시 다시 시도할 수 있다. |
| NFR-10 | 보안 | API 키와 내부 정보가 노출되지 않는다. | 키는 환경 변수로만 관리하고 `.gitignore`에 넣는다(프론트엔드 설정은 `config.example.js`만 저장소에 두고, 배포 시 Vercel 환경변수로 생성). `firestore.rules`로 브라우저의 DB 직접 접근을 모두 차단하고, 제출 전 `backend/scripts/check_secrets.py`로 저장소를 검사한다(0건). CORS는 배포 도메인만 허용하고, 입력은 Pydantic으로 검증한다. 500 응답에 내부 오류 내용을 노출하지 않으며, 화면은 textContent로 렌더링해 XSS를 막는다. |
| NFR-11 | 테스트 가능성 | API 키 없이 핵심 규칙을 검증할 수 있다. | `DB_BACKEND=memory`와 가짜 토큰으로 `tests/test_api.py`를 실행한다. Agent는 정해진 응답을 흉내 내는 가짜 모델로 루프를 검증한다. |
| NFR-12 | 화면 | 데스크톱·모바일·다크 모드에서 읽을 수 있다. | 반응형으로 3단에서 1단으로 바뀌고, 표는 가로 스크롤, 차트는 라이트·다크 색을 따로 둔다. |

## 3. 시스템 아키텍처

### 3-1. 전체 구성

프론트엔드는 로그인으로 받은 ID 토큰을 붙여 백엔드만 호출한다. Firestore와 OpenAI 키는 백엔드에만 있으며, 브라우저는 데이터베이스나 AI에 직접 접근하지 않는다.

![시스템 아키텍처](images/system_architecture.png)

강조된 상자가 AI Agent 도구이다. AI 코치(chat_service)가 Function Calling으로 도구를 호출하고, 도구는 거래·요약·목표 서비스를 읽기 전용으로 조회한다. 소비 알림 카드(`/api/insights`)는 같은 과소비 규칙을 AI 없이 호출해 카드를 만든다.

### 3-2. 구성 요소

| 구성 요소 | 기술 | 역할 |
| --- | --- | --- |
| 프론트엔드 | HTML, CSS, JavaScript(ES 모듈), Firebase JS SDK | 로그인, 이미지 업로드·확인 표, 요약·차트, 목표 카드, 채팅 화면(근거·제안 카드) |
| 인증 | Firebase Authentication | Google 로그인, 익명 로그인(체험 모드), ID 토큰 발급 |
| 백엔드 | Python 3.12, FastAPI, Pydantic | 토큰 검증, 요청 검증, 비즈니스 로직, AI 호출 |
| 데이터베이스 | Firebase Firestore | 사용자별 하위 컬렉션에 거래·목표·대화 저장 |
| AI | OpenAI gpt-4o-mini | 이미지 인식(Vision + Structured Outputs), Agent 도구 선택(Function Calling), 답변 생성 |
| 배포 | Vercel(프론트엔드), Render(백엔드) | 정적 페이지 배포, API 서버 배포 |

### 3-3. AI 코치(Agent) 처리 흐름

1. 사용자가 질문을 보내면 서버가 오늘 날짜, 데이터 범위, 목표 유무, 규칙을 담은 시스템 프롬프트와 도구 7개의 설명을 모델에 전달한다.
2. 모델이 필요한 도구와 인자를 정한다. 도구가 필요 없는 질문이면 바로 답한다.
3. 서버가 인자를 검증하고 로그인한 사용자 ID로 도구를 실행한 뒤, 결과를 모델에 돌려준다. 인자가 잘못되면 오류 내용을 돌려주어 모델이 고쳐서 다시 부르게 한다.
4. 모델은 결과를 보고 추가 조회 여부를 다시 판단한다. 최대 5단계, 단계당 최대 4개까지 실행한다.
5. 답변이 완성되면 서버가 검사한다. [적용]을 안내했는데 목표 제안 도구를 부르지 않았다면 한 번 다시 요청한다.
6. 답변, 조회 근거(trace), 목표 제안(actions)을 함께 저장하고 화면에 돌려준다.

### 3-4. 데이터 모델

모든 데이터는 `users/{uid}` 아래에 두어 사용자끼리 섞일 수 없다.

| 경로 | 주요 필드 | 비고 |
| --- | --- | --- |
| `users/{uid}` | email, consent_version, consent_at, chat_usage, image_usage | 동의 버전과 하루 사용량 |
| `users/{uid}/transactions/{id}` | date, amount, merchant, category, source, category_by, memo, created_at | source: manual·screenshot·receipt·sample, category_by: ai·user·rule |
| `users/{uid}/goals/{YYYY-MM}` | total_budget, category_limits[≤3], history[], updated_at | 월별 문서, 변경 전 값은 history에 누적 |
| `users/{uid}/conversations/{id}` | title, messages[], updated_at | 답변 메시지마다 조회 근거(trace)와 목표 제안(actions) 저장 |

### 3-5. API

| Method | Path | 설명 |
| --- | --- | --- |
| GET · POST · DELETE | `/api/me`, `/api/me/consent`, `/api/me/demo` | 내 정보·동의, 전체 삭제, 체험 데이터 생성 |

## 4. AI 활용 명세

AI는 이미지 읽기, 조회 도구 선택, 답변·제안 작성에만 사용하고, 금액·날짜·중복·목표 계산 등 나머지 판단은 코드 규칙이 맡는다. 모델은 모두 OpenAI gpt-4o-mini이며 환경 변수(`OPENAI_MODEL`, `OPENAI_VISION_MODEL`)로 바꿀 수 있다.

### 4-1. 기능별 AI 활용 방식

| 기능 | 기술 요소 | AI가 하는 일 | 코드가 하는 일 · 안전장치 |
| --- | --- | --- | --- |
| 캡처·영수증 인식 (FR-05) | 멀티모달 AI | 이미지 1장에서 이미지 종류와 거래를 읽는다. 목록 화면은 날짜 머리글마다 묶음(section)을 만들고 그 아래 거래(가맹점, 금액, 돈의 방향, 확신도)를 넣으며, 날짜는 화면 글자 그대로(date_text) 적는다. JSON 스키마를 강제해(Structured Outputs) 정해진 형식으로만 답한다. | 브라우저에서 이미지를 축소해 보낸다. 0원·빈 가맹점을 제거하고, 원본 이미지는 저장하지 않는다. |
| 날짜·중복·입금 판단 (FR-06~08) | 코드 규칙 | 없음 | 날짜 글자 재해석(AI가 채운 월·연도는 글자에 없으면 버림), 연도·월 결정과 요일 확인, 기존 거래와의 동일·유사 중복 판단, 입금·취소 체크 해제를 코드로 처리하고, 확인 표에서 사람이 확인한다. |
| 카테고리 분류 (FR-09) | 멀티모달 AI + 규칙 저장 | 고정 12개 카테고리 중 하나를 추천한다. | 사용자가 고친 가맹점 분류 규칙이 있으면 AI 분류 대신 그 규칙을 적용한다. |
| AI 코치 답변 (FR-14) | AI Agent | 도구로 조회한 결과만 근거로 답변을 작성한다. | 이전 대화는 질문·답변 글만 최대 10개 전달하고, 숫자는 매번 도구로 다시 조회한다. 답변은 500 토큰으로 제한한다. 비교용 이전 방식(요약 주입)은 `COACH_MODE=baseline`으로 유지한다. |
| Agent 도구 선택 (FR-15) | AI Agent | 질문 의도를 보고 도구 7개 중 필요한 것을 골라 호출하고(Function Calling), 결과를 보고 추가 조회 여부를 다시 판단한다. 목표 변경이 필요하면 제안을 작성한다. | 도구는 읽기 전용이며 사용자 ID는 서버가 넣는다. 인자는 Pydantic으로 검증하고 오류는 모델에 돌려준다. 최대 5단계·단계당 4개로 제한한다. 진행 중인 달은 같은 기간끼리 비교하고, 이미 쓴 금액보다 낮은 한도는 거부한다. [적용]을 안내했는데 제안이 없으면 1회 다시 요청한다. |
| 과소비 탐지 (FR-16) | AI Agent(도구) + 코드 규칙 | 탐지 결과를 해석해 절약 방법을 설명한다. | 직전 3개월 평균의 130% 이상·2만 원 이상 증가 여부, 목표 초과 여부는 코드가 판정한다. |
| 소비 알림 카드 (FR-24) | 코드 규칙 → 버튼 클릭 시 AI Agent | 카드의 버튼을 누르면 Agent가 원인 분석·목표 제안을 한다. | 카드 내용(과소비·목표 초과)은 코드가 계산해 접속 시 AI 비용이 들지 않는다. 화면에 "규칙으로 계산"이라고 표시해 AI 결과와 구분한다. |
| 목표 추천 (FR-12) | 코드 규칙 | 없음 (비용 0) | 최근 3개월 평균에서 총예산 −10%, 고정비를 뺀 상위 3개 카테고리 −15%로 계산한다. 진행 중인 달은 이미 쓴 금액의 110%보다 낮게 잡지 않는다. |
