# AI 소비 패턴 분석 및 절약 코치 — 서비스 기획서

## 1. 서비스 개요

### 1-1. 서비스 소개

**AI 소비 패턴 분석 및 절약 코치**는 카드 이용내역 캡처 이미지와 영수증을 기반으로 개인의 지출 데이터를 자동 수집·분류하고, 소비 패턴 분석 및 맞춤형 절약 전략을 제공하는 AI 기반 소비 관리 서비스이다.

사용자가 소비 내역을 이미지로 업로드하면 AI가 거래 정보를 추출하고, 시스템이 데이터를 정리·집계하여 월별 소비 현황과 카테고리별 지출 비중을 시각화한다.

또한 사용자가 설정한 월별 예산과 소비 목표, 누적된 지출 데이터를 바탕으로 AI 코치가 소비 습관을 분석하고 실천 가능한 절약 방안을 제안한다. AI 코치는 질문에 답하기 위해 필요한 데이터를 스스로 선택하여 조회하고, 조회한 근거를 답변과 함께 제시한다.

단순한 지출 기록과 통계 제공을 넘어, 사용자가 자신의 소비 행동을 이해하고 지속적으로 개선할 수 있도록 지원하는 것을 목표로 한다.

### 1-2. 서비스 핵심 가치

| 구분 | 제공 가치 |
| --- | --- |
| 기록 자동화 | 카드 내역 캡처 및 영수증 이미지에서 거래 정보를 자동 추출하여 수기 입력 부담을 줄인다. |
| 소비 분석 | 월별·카테고리별 소비 데이터를 분석하여 주요 지출 항목과 소비 변화 추이를 파악할 수 있도록 한다. |
| 목표 관리 | 월별 예산 및 카테고리별 소비 한도를 설정하고, 진행 상황과 달성률을 확인할 수 있도록 한다. |
| 개인화 코칭 | AI 코치가 사용자의 실제 거래 데이터와 목표를 직접 조회하여, 근거가 확인되는 맞춤형 절약 전략을 제안한다. |
| 지속적인 관리 | 누적된 소비 기록, 목표 변경 이력, 사용자가 수정한 분류 규칙을 저장·재사용하여 지속적인 소비 관리 경험을 제공한다. |

## 2. 문제 정의

소비 관리의 어려움은 단순히 지출을 기록하는 문제에 그치지 않는다. 자신의 소비 데이터를 지속적으로 관리하고, 지출 내역을 해석하여 실제 행동 변화로 이어지도록 하는 과정에서 여러 어려움이 발생한다.

| 문제 영역 | 사용자 문제 | 기존 방식의 한계 |
| --- | --- | --- |
| 소비 기록 | 카드 및 은행 앱에 분산된 지출 내역을 정리하기 어렵다. | 수기 입력과 반복적인 기록 과정으로 인해 가계부 사용이 중단되기 쉽다. |
| 소비 분석 | 어떤 항목에 돈을 많이 사용하고 있는지, 이전보다 지출이 증가했는지 파악하기 어렵다. | 합계와 그래프만 제공하는 경우 소비 증가 원인이나 개선 방향을 스스로 분석해야 한다. |
| 절약 실천 | 소비를 줄여야 한다는 생각은 있지만 구체적인 실천 방법을 찾기 어렵다. | 단순한 예산 설정만으로는 소비 행동을 지속적으로 관리하기 어렵다. |
| 지속 관리 | 소비 목표를 설정하더라도 중간 점검과 동기 부여가 부족하다. | 일회성 기록과 분석에 그쳐 장기적인 소비 습관 개선으로 이어지기 어렵다. |
| AI 답변 신뢰 | AI에게 소비 상담을 받아도 답변의 숫자가 실제 내 데이터와 맞는지 확인하기 어렵다. | 일반적인 AI 채팅은 데이터 근거 없이 그럴듯한 숫자를 만들어 낼 수 있다. |

### 2-1. 해결 방향

본 서비스는 소비 관리 과정에서 발생하는 기록, 분석, 실천의 어려움을 AI와 데이터 기반 관리 기능으로 해결하고자 한다.

- **기록 자동화:** 이미지 기반 거래 정보 추출 기능을 통해 지출 기록 과정의 편의성을 높인다.
- **데이터 기반 분석:** 정확한 지출 집계와 시각화를 통해 소비 현황을 객관적으로 파악할 수 있도록 한다.
- **목표 중심 관리:** 월별 예산과 카테고리별 소비 한도를 설정하고, 목표 대비 소비 현황을 지속적으로 확인할 수 있도록 한다.
- **근거 있는 코칭:** AI Agent가 질문에 필요한 데이터를 직접 조회한 뒤 답변하고, 어떤 데이터를 근거로 삼았는지 화면에 함께 표시한다.

## 3. 타겟 사용자

### 3-1. 핵심 타겟 사용자

본 서비스의 핵심 타겟은 **생활비와 개인 소비 지출을 스스로 관리해야 하지만, 소비 기록을 지속하기 어렵거나 지출 분석 및 절약 실천에 어려움을 겪는 대학생, 사회초년생 및 초기 직장인**이다.

특히 소비 내역이 여러 금융 앱에 분산되어 있고, 소비 관리의 필요성을 느끼지만 기존 가계부 사용 경험에서 기록 부담이나 분석의 어려움을 경험한 사용자를 주요 대상으로 설정한다.

| 주요 사용자 | 특징 및 소비 관리 문제 | 서비스 활용 기대 |
| --- | --- | --- |
| 생활비를 관리하는 대학생 | 용돈, 아르바이트 수입 등 제한적인 예산 안에서 생활하며 배달, 카페, 쇼핑 등 생활 지출을 관리해야 한다. | 한정된 예산 안에서 소비 현황을 파악하고, 우선적으로 줄일 지출 항목을 찾는다. |
| 사회초년생 및 초기 직장인 | 월급을 받기 시작했지만 저축과 소비의 균형을 잡기 어렵고, 월급 대비 지출 관리에 어려움을 겪는다. | 월급 내 소비 구조를 파악하고, 월별 예산과 저축 목표에 맞는 소비 계획을 세운다. |
| 가계부 사용 중단 경험자 | 기록 과정이 번거롭거나 소비 내역을 기록해도 의미 있는 분석을 얻지 못해 가계부 사용을 중단한 경험이 있다. | 기록 부담을 줄이고, 분석 결과와 AI 코칭을 통해 소비 관리의 지속성을 높인다. |

### 3-2. 핵심 사용자 페르소나

**페르소나 A — 생활비 관리가 필요한 대학생**

- 상황: 월별 생활비가 정해져 있지만 배달, 카페, 쇼핑 등에 지출이 반복적으로 발생한다.
- 문제: 월말이 되면 돈이 부족하지만 어디서 지출이 늘었는지 정확히 알지 못한다.
- 니즈: 남은 생활비를 확인하고, 다음 달에는 어떤 소비를 줄여야 할지 알고 싶다.
- 기대 효과: 소비 내역을 자동으로 정리하고, 현실적인 지출 한도를 설정하여 생활비를 효율적으로 관리한다.

**페르소나 B — 저축을 시작하고 싶은 사회초년생**

- 상황: 첫 월급 또는 초기 직장 생활을 시작하면서 저축과 소비 관리에 관심이 생겼다.
- 문제: 월급을 받지만 매달 지출이 반복되고, 계획한 저축 금액을 확보하기 어렵다.
- 니즈: 자신의 소비 패턴을 파악하고, 저축 목표를 달성하기 위해 조정해야 할 소비 항목을 알고 싶다.
- 기대 효과: 월별 소비 데이터를 기반으로 예산을 관리하고, 소비 목표와 저축 계획을 지속적으로 점검한다.

### 3-3. 사용자 이용 시나리오

1. 사용자는 Google 계정으로 로그인하거나 체험 모드로 서비스에 접속한다.
2. 카드 또는 은행 앱 이용내역 화면을 캡처하여 업로드한다.
3. AI가 거래 날짜, 가맹점명, 금액, 거래 유형 및 카테고리를 추출한다.
4. 사용자는 추출된 정보를 확인하고 잘못된 항목을 수정한 뒤 저장한다.
5. 저장된 데이터를 기반으로 월별 소비 현황, 카테고리별 지출 비중 및 소비 추이를 확인한다.
6. 사용자는 월별 소비 목표와 카테고리별 한도를 설정한다.
7. AI 코치에게 소비 현황과 목표에 대한 질문을 하거나 절약 전략을 요청한다.
8. AI 코치는 질문에 필요한 조회 도구를 스스로 선택·실행하고, 그 결과를 근거로 답변한다. 답변 아래에는 AI가 조회한 데이터 목록(근거)이 함께 표시된다.
9. 사용자가 목표 설정을 요청하면 AI 코치는 목표안을 제안 카드로 보여주고, 사용자가 [적용]을 눌렀을 때만 저장된다.
10. 사용자는 소비 관리 결과와 코칭 경험에 대한 피드백을 제공하고, 해당 피드백은 서비스 개선에 반영된다.

## 4. AI 활용 방식

### 4-1. AI 활용 전략

본 서비스는 AI를 단순한 대화형 인터페이스가 아닌, 소비 데이터의 입력 처리와 데이터 기반 소비 코칭에 활용한다. 핵심 AI 기술 요소로 **멀티모달 AI**와 **AI Agent** 두 가지를 적용한다.

| AI 기술 요소 | 적용 기능 | 활용 목적 |
| --- | --- | --- |
| 멀티모달 AI | 이미지 기반 거래 데이터 추출 | 카드·은행 앱 캡처와 영수증 이미지에서 거래 정보를 추출하고, 구조화된 데이터로 변환한다. |
| AI Agent | Function Calling 기반 데이터 조회·분석 도구 호출 | 모델이 질문 의도를 파악하여 7개 도구 중 필요한 것을 직접 선택·실행하고, 결과를 보고 추가 조회 여부를 다시 판단한 뒤 근거 기반 답변을 생성한다. |

나머지 기술 요소는 다음 근거로 적용하지 않았다.

| 기술 요소 | 적용 여부 | 근거 |
| --- | --- | --- |
| RAG | 미적용 | 코치가 참고할 대상은 문서가 아니라 사용자의 거래 데이터(금액·날짜·카테고리)이다. 기간 합계·비교처럼 정확한 집계가 필요한 질문에는 임베딩 검색보다 코드로 집계하는 Agent 도구가 정확하다(평가에서 지어낸 숫자 0건, 4-6절). |
| 자동화 워크플로우 | 미적용(향후 확장) | 필수 요소 2개(멀티모달 AI, AI Agent)로 조건을 충족한다. 월간 리포트 이메일(n8n)은 시간이 남으면 추가한다. |
| Long-term Memory | 미적용(향후 확장) | 4-4절 참고. |

### 4-2. 멀티모달 AI — 소비 데이터 자동 추출

사용자가 업로드한 이미지에서 거래 날짜, 가맹점명, 금액 등의 정보를 추출하고, 거래 유형 및 소비 카테고리를 분류하는 데 AI를 활용한다.

- 입력: 카드·은행 앱 이용내역 캡처, 거래 상세 화면, 종이 영수증
- 출력: 거래 날짜, 가맹점명, 거래 금액, 거래 유형, 카테고리 등의 구조화된 데이터
- 처리 방식: 목록 화면은 날짜 머리글별 묶음으로 읽고, 날짜는 화면 글자 그대로 받아 코드가 연·월·일을 정한다. AI가 추출한 데이터는 저장 전 사용자 검증 단계를 거친다.
- 활용 목적: 수기 입력 부담을 줄이고, 일관된 형태의 소비 데이터 확보

### 4-3. AI Agent — 데이터 기반 소비 코칭

AI Agent는 사용자의 질문을 분석하고, 질문에 답하기 위해 필요한 데이터 조회 도구를 **모델이 직접 선택·실행**한 뒤 결과를 바탕으로 답변을 생성한다. 코드에는 "이 질문이면 이 도구를 쓴다"는 분기가 없으며, 도구 선택과 조회 순서는 모두 모델이 판단한다.

**동작 흐름**

1. 사용자 질문과 함께 도구 7개의 설명을 모델에 전달한다.
2. 모델이 필요한 도구와 인자(기간, 카테고리, 가맹점 등)를 정한다. 한 번에 여러 도구를 부를 수 있다.
3. 서버가 도구를 실행하고 결과(코드로 계산한 숫자)를 모델에 돌려준다.
4. 모델은 결과를 보고 추가 조회가 필요한지 다시 판단한다. 필요하면 2~3단계를 반복한다(최대 5단계).
5. 충분한 근거가 모이면 답변을 생성하고, 화면에는 답변과 함께 조회한 도구·조건·결과 요약(근거)을 표시한다.

**Agent 도구 목록**

| 도구 | 기능 |
| --- | --- |
| 거래 검색 | 기간·가맹점·카테고리·최소 금액으로 거래를 찾아 건수, 합계, 가맹점별 집계를 돌려준다. |
| 월 요약 | 한 달의 총지출, 카테고리별 비중, 상위 가맹점, 지난달 대비 변화, 월말 예상을 돌려준다. |
| 두 달 비교 | 두 달의 총지출과 카테고리별 증감을 비교하고, 늘어난 카테고리 목록을 돌려준다. |
| 카테고리 추이 | 한 카테고리의 최근 N개월 월별 금액과 평균을 돌려준다. |
| 과소비 탐지 | 직전 3개월 평균 대비 130% 이상이면서 2만 원 이상 늘어난 카테고리와 목표 초과 항목을 찾는다. |
| 목표 진행 상황 | 이번 달 목표 대비 사용률, 월말 예상, 하루 사용 가능 금액을 돌려준다. 목표가 없으면 추천안을 돌려준다. |
| 목표 변경 제안 | 목표안을 검증하여 제안 카드로 만든다. 저장하지 않으며, 사용자가 [적용]을 눌러야 저장된다. |

**질문별 도구 선택 예시**

| 사용자 질문 예시 | 모델이 선택한 도구 | 제공 결과 |
| --- | --- | --- |
| 이번 달에 카페 몇 번 갔어? | 거래 검색 | 해당 기간 카페 거래 건수와 합계 |
| 지난달보다 이번 달에 뭐가 늘었어? | 두 달 비교 | 같은 기간 기준 카테고리별 증감 금액과 증가율 |
| 요즘 어디서 돈이 새고 있어? | 과소비 탐지 | 평소보다 크게 늘어난 카테고리 |
| 이번 달 목표 지킬 수 있을까? | 목표 진행 상황 | 목표 대비 사용률과 월말 예상 |
| 배달을 줄이고 싶어. 이번 달 목표를 만들어줘 | 목표 진행 상황 → 월 요약 → 목표 변경 제안 | 이미 쓴 금액을 고려한 목표안과 [적용] 버튼 |
| 늘어난 카테고리가 있으면 그 추이도 보여줘 | 두 달 비교 → 카테고리 추이 | 여러 단계 조회: 비교 결과를 보고 추이를 추가 조회 |
| 돈 아끼는 일반적인 팁 알려줘 | (도구 없음) | 데이터가 필요 없는 질문은 조회 없이 답변 |

**안전장치**

- 모든 조회 도구는 읽기 전용이다. AI가 사용자의 데이터를 직접 수정하지 않으며, 목표 변경은 제안만 하고 저장은 사용자가 결정한다.
- 사용자 ID는 모델이 아닌 서버가 넣는다. 모델이 어떤 인자를 보내더라도 로그인한 사용자 본인의 데이터만 조회된다.
- 도구 인자는 서버에서 검증하며, 잘못된 인자는 오류 내용을 모델에 돌려주어 모델이 스스로 고쳐 다시 호출하게 한다.
- 조회 단계는 최대 5단계, 한 단계의 도구 호출은 최대 4개로 제한한다.
- 답변이 [적용] 버튼을 안내했는데 실제로 목표 제안 도구를 부르지 않았다면, 서버가 이를 검사하여 모델에게 한 번 다시 요청한다.
- 도구를 여러 번 호출하더라도 사용자의 질문 1개는 하루 이용 한도 1회로 계산한다.

### 4-4. 개인화 기능 — 사용자 수정 내용의 저장과 재사용

사용자가 한 번 수정하거나 설정한 내용은 저장하여 다음 이용에 다시 활용한다. 이 기능은 AI가 대화에서 정보를 추출하는 장기 메모리가 아니라, 사용자의 명시적인 행동을 규칙으로 저장하는 방식이다.

- **분류 규칙:** 사용자가 이미지 인식 결과의 카테고리를 직접 수정하면 가맹점별 규칙으로 저장하고, 이후 같은 가맹점은 수정된 카테고리로 분류한다.
- **목표 이력:** 월별 목표와 변경 이력을 저장하며, 새 달에 목표가 없으면 직전 목표를 이어서 적용한다.

**대화 기억(Long-term Memory)은 향후 확장 기능으로 둔다.** 대화에서 사용자의 소비 성향과 절약 이유를 추출해 다음 대화에 반영하는 기능은 코칭을 더 개인화할 수 있지만, 서비스의 핵심 문제(기록·분석·실천)를 해결하는 데 필수 요소는 아니다. 본 프로젝트는 멀티모달 AI와 AI Agent의 완성도, 그리고 실사용자 테스트와 피드백 반영을 우선하였다. 사용자 테스트에서 이전 대화 내용을 기억하지 못하는 점이 주요 불편으로 확인되면 추가를 검토한다.

### 4-5. AI 활용 원칙

**AI의 해석과 제안은 활용하되, 금액 및 통계 데이터의 정확성은 시스템 로직으로 보장하는 것을 원칙으로 한다.**

- 합계, 평균, 비율, 목표 잔액, 달성률 및 월말 예상은 코드로 계산한다.
- AI는 도구로 조회한 결과에 있는 숫자만 사용하여 설명 및 제안을 제공한다.
- 데이터 조회가 불가능하거나 근거가 부족한 경우 임의의 숫자를 생성하지 않고, 정보 부족을 명시한다.
- 진행 중인 달은 지난달의 같은 기간(1일~오늘)과 비교하여, 끝나지 않은 달과 끝난 달을 그대로 비교하는 왜곡을 막는다.
- AI는 데이터를 직접 변경하지 않으며, 목표 변경 등 데이터를 바꾸는 행동은 사용자의 확인을 거친다.
- 이미지 인식 결과는 사용자가 확인 및 수정한 후 저장한다.
- AI가 생성한 분석 및 제안에는 AI 생성 결과임을 표시하고, AI가 조회한 근거를 함께 보여준다.

### 4-6. 기술적 의사결정 — 요약 주입 방식에서 AI Agent로

초기 AI 코치는 사용자의 지출 요약(월별·카테고리별 합계)을 프롬프트에 넣어 답변하는 방식이었다. 테스트 과정에서 다음 한계가 확인되어 AI Agent 방식으로 전환하였다.

| 확인된 문제 | 원인 | Agent 방식에서의 해결 |
| --- | --- | --- |
| "이번 달 카페 몇 번 갔어?", "지난달 택시 몇 번 탔어?" 같은 개별 거래 질문에 답하지 못하거나 추측함 | 요약에는 개별 거래가 없음 | 모델이 거래 검색 도구로 해당 거래를 직접 조회 |
| 요약에 없는 금액을 그럴듯하게 만들어 답함 | 모델이 근거 없이 숫자를 생성할 수 있음 | 숫자는 도구 결과에 있는 값만 쓰도록 하고, 근거를 화면에 공개 |
| 질문과 무관한 요약 전체를 매번 전달 | 질문에 필요한 데이터를 고를 수 없음 | 질문에 필요한 데이터만 골라 조회 |

**전환 효과 평가 (2026-11-20, 3회 반복 실행)**

체험 데이터와 질문 15개(개별 거래, 월 비교, 추이, 과소비, 목표, 여러 단계 질문, 도구가 필요 없는 질문)로 두 방식을 비교하였다. 정답은 같은 데이터를 코드로 직접 계산하여 정하였다. 생성형 AI의 답변은 실행할 때마다 달라질 수 있으므로 같은 평가를 3회 반복하였다.

| 지표 | AI Agent | 이전 방식(요약 주입) |
| --- | --- | --- |
| 도구 선택 정확도 | 15/15 (3회 모두) | 해당 없음 |
| 정답 일치(정답이 정해진 10개 질문) | 9/10 (3회 모두) | 5/10 (3회 모두) |
| 숫자 근거율(지어낸 숫자가 없는 답변) | 15/15 (3회 모두) | 평균 12.3/15 (12, 13, 12) |

- 이전 방식이 틀린 질문 5개는 모두 개별 거래나 카테고리 추이처럼 요약만으로는 알 수 없는 질문이었다(카페 방문 횟수, 스타벅스 지출, 택시 이용 횟수, 10만 원 이상 거래, 배달비 6개월 추이).
- Agent가 틀린 1개(월말 예상 지출)는 3회 모두 같은 질문에서 발생하여 원인을 분석하였다. 아래 개선 표의 마지막 항목이 그 결과이다.
- 이 문제를 수정한 뒤 다시 평가한 결과(2026-11-20, 1회) Agent는 도구 선택 15/15, 정답 일치 10/10, 숫자 근거율 15/15를 기록하였다. 이전 방식은 정답 일치 5/10으로 변화가 없었다.
- 평가 질문 15개는 문제를 찾고 고치는 데에도 사용하였으므로, 이 결과만으로 처음 보는 질문에서도 같은 성능이 나온다고 단정할 수 없다. 실사용자 테스트에서 수집한 실제 질문으로 추가 검증한다.
- 숫자 근거율은 답변의 금액·비율이 근거 데이터에 있는지 자동으로 확인하는 방식이다. 초기 판정 방식은 '-46.7%'를 '46.7% 감소'로 쓴 답변을 근거 없음으로 잘못 판정하여, 부호를 무시하도록 수정한 뒤 측정하였다.

**소비 알림 카드 — Agent를 먼저 제안하는 화면으로 연결**

채팅 첫 화면에 과소비·목표 초과 알림 카드를 최대 2개 보여준다. 카드 내용은 과소비 탐지 규칙과 목표 진행률로 코드가 계산하므로 접속할 때 AI 비용이 들지 않는다. 사용자가 카드의 [자세히 분석하기] 또는 [목표로 관리하기]를 누르면 AI Agent가 원인 분석이나 목표 제안을 이어서 하고, 사용자가 [적용]을 눌러 실행한다(알림 → 분석·제안 → 실행). 화면에는 "규칙으로 계산"이라고 표시해 AI가 만든 내용과 구분한다.

**Agent 테스트에서 발견하여 개선한 문제**

| 발견한 문제 | 개선 내용 |
| --- | --- |
| 20일까지만 진행된 이번 달을 지난달 전체와 비교하여, 모든 카테고리가 "감소"로 나옴 | 진행 중인 달은 두 달 모두 1일~오늘 기준으로 비교. 같은 데이터에서 "총지출 46.7% 감소"가 "총지출 5.5% 증가, 식비 46.6% 증가"로 바로잡힘 |
| 목표 추천 시 이번 달에 이미 쓴 금액보다 낮은 한도를 제안함 (식비 277,200원 사용 중 한도 270,000원) | 진행 중인 달은 이미 쓴 금액 이상으로 한도를 잡고, 제안 도구가 이를 검증하여 위반 시 모델이 다시 제안하게 함 |
| 목표안을 글로만 쓰고 제안 도구를 부르지 않아 [적용] 버튼이 나타나지 않음 | 프롬프트 규칙을 명확히 하고, 서버가 답변을 검사하여 한 번 다시 요청 |
| 늘어난 카테고리를 찾는 질문에서 모든 카테고리 추이를 한꺼번에 조회함(12회) | 비교 결과에 늘어난 카테고리 목록을 포함하고, 한 단계 호출 수를 4개로 제한. 이후 평가에서는 실제로 늘어난 4개 카테고리만 조회함 |
| "월말까지 얼마 쓸 것 같아?"에 3회 연속 오답 | 모델은 설명에 '월말 예상'이 적힌 목표 진행 상황 도구를 골랐지만, 이 도구는 목표가 없으면 월말 예상을 돌려주지 않았음. 도구 설명과 실제 결과가 어긋난 설계 문제로, 목표가 없어도 현재 지출과 월말 예상을 함께 돌려주도록 수정 |

## 5. 기술적 접근 및 기술 스택 선정

### 5-1. 기술적 접근 방향

본 서비스는 소비 데이터의 정확한 저장 및 관리와 AI 기반 분석·코칭을 분리하여 설계한다.

거래 데이터의 추출, 검증, 집계 및 목표 계산은 시스템 로직을 중심으로 처리하고, AI는 이미지 인식, 질문 의도 파악, 데이터 조회 도구 선택, 데이터 기반 해석 및 절약 전략 제안에 활용한다. AI Agent의 도구는 시스템 로직을 감싼 읽기 전용 인터페이스로, AI는 도구를 통해서만 사용자 데이터에 접근한다.

또한 사용자별 데이터 접근을 분리하고, 지속적인 소비 관리에 필요한 데이터가 안전하게 저장·활용될 수 있도록 인증 및 데이터 관리 구조를 구축한다.

### 5-2. 기술 스택 선정 이유

| 영역 | 기술 | 선정 이유 |
| --- | --- | --- |
| Backend | Python 3.12, FastAPI, Pydantic | Python 기반 AI 라이브러리와의 호환성이 높으며, FastAPI의 요청 검증 및 API 문서 자동 생성 기능을 활용하여 백엔드 구현과 테스트 효율을 높인다. Pydantic은 AI Agent 도구 인자 검증에도 사용한다. |
| Database | Firebase Firestore | 사용자별 데이터 관리에 적합한 문서형 데이터베이스이며, 사용자 ID 기반 하위 컬렉션 구조를 통해 데이터 분리 및 관리가 용이하다. |
| Authentication | Firebase Authentication | Google 로그인과 익명 로그인 기능을 활용하여 비밀번호 직접 관리 없이 사용자 인증을 구현하고, 체험 모드를 제공할 수 있다. |
| AI | OpenAI API, gpt-4o-mini | 이미지 입력, 구조화된 데이터 출력(Structured Outputs) 및 도구 호출(Function Calling) 기능을 하나의 모델로 활용할 수 있으며, 비교적 낮은 비용으로 AI 기능을 구현하고 테스트할 수 있다. |
| Frontend | HTML, CSS, JavaScript, Firebase JS SDK | 별도의 프론트엔드 빌드 환경 없이 구현할 수 있으며, 기존 웹 개발 학습 경험을 활용하여 기능 구현과 배포를 단순화한다. |
| Visualization | SVG 기반 차트 | 외부 차트 라이브러리 의존성을 줄이고, 소비 데이터의 시각화와 UI 디자인을 직접 제어할 수 있다. |
| Deployment | Vercel, Render | 프론트엔드와 백엔드를 분리 배포할 수 있으며, 기존 프로젝트에서 검증한 배포 환경을 재사용하여 개발 및 운영 부담을 줄인다. |
| Testing | FastAPI TestClient, Playwright, Agent 평가 스크립트 | API 로직, 사용자별 데이터 접근, 소비 데이터 처리 및 웹 화면 흐름을 자동 검증한다. Agent 평가 스크립트는 같은 질문으로 Agent와 이전 방식을 비교하여 도구 선택 정확도와 정답 일치를 측정한다. |

### 5-3. 시스템 운영 및 비용 관리 방향

- 이미지 업로드 시 브라우저에서 이미지 크기를 축소하여 전송 비용과 처리 부담을 줄인다.
- 일일 AI 요청 횟수(채팅 50회) 및 이미지 업로드 수(30장)를 제한하여 API 사용 비용을 관리한다.
- AI 응답 토큰 상한을 설정하고, 반복적으로 조회하는 소비 요약은 캐싱하여 불필요한 호출을 줄인다.
- AI Agent는 도구 결과를 받을 때마다 모델을 다시 호출하므로 질문 1개당 비용이 이전 방식보다 높다(약 2~4배, 질문당 수 원 수준). 조회 단계(최대 5단계)와 단계당 호출 수(최대 4개)를 제한하여 비용 증가 폭을 관리한다.
- 월초와 같이 데이터가 충분하지 않은 시점에는 월말 소비 예측을 제공하지 않거나 제한적으로 제공한다.
- 인증 및 사용자별 데이터 접근 권한을 검증하고, 개인 소비 데이터의 접근 범위를 제한한다.

### 6-2. 현재 개발 진행 상황

현재 사용자 인증, 이미지 인식, 거래 관리, 소비 요약 및 차트, 월별 목표 관리와 AI Agent 기반 소비 코칭을 구현한 상태이다.

AI 코치는 7개의 조회·분석 도구를 스스로 선택하여 사용하며, 과소비 탐지와 목표 제안 기능을 포함한다. 질문 15개로 구성한 평가를 3회 반복한 결과, 정답 일치가 이전 방식 5/10에서 Agent 9/10으로 개선되었고, 남은 오답의 원인(도구 설명 불일치)을 고친 뒤에는 10/10을 기록하였다. 또한 평가 과정에서 발견한 비교 기준 왜곡, 목표 한도 오류, 도구 설명 불일치 등을 수정하였다.

서비스는 https://final-project-frontend-seven-beta.vercel.app 에 배포되어 있으며, 로그인 없이 체험 모드로 사용할 수 있다. 이미지 인식은 평가용 샘플 이미지로 3회 반복 확인하였고(4-7절), 기능 요구 명세서의 Must 16개를 모두 구현하였다. 이후 실사용자 테스트와 피드백 반영을 진행한다.

### 6-3. 사용자 테스트 계획

실제 소비 관리 경험이 있는 사용자 5명 이상(목표 6~8명)을 대상으로 서비스를 테스트하고, 기능의 사용성 및 AI 코칭의 실효성을 검증한다.

- 대상: 팀원은 제외한다. 3장의 타겟 사용자(생활비를 관리하는 대학생, 사회초년생, 가계부 사용 중단 경험자)에 해당하는 사람만 참여하며, 참여자마다 타겟 해당 근거를 기록한다.
- 개인정보: 이름·연락처는 수집하지 않고 T1, T2 …의 가명으로만 기록한다. 테스트 중 본인 카드 내역 대신 체험 모드와 평가용 샘플 이미지를 사용할 수 있게 한다.
- 진행: 15분 미션(접속·동의 → 샘플 이미지 업로드·저장 → 목표 설정 → 소비 알림 카드와 AI 코치 질문 → 설문)을 수행한 뒤 설문에 답한다. 진행 안내와 설문 문항은 `docs/UT_GUIDE.md`에 둔다.
- 반영: 피드백 중 상위 2~3건을 코드에 반영하고, 반영 커밋과 전후 화면 또는 미반영 사유를 `docs/USER_FEEDBACK.md`에 기록한다.

| 평가 항목 | 측정 방법 | 검증 목적 |
| --- | --- | --- |
| 데이터 인식 정확도 | 인식 결과의 사용자 수정 비율 확인 | 이미지 기반 거래 데이터 추출의 정확성 평가 |
| 기록 편의성 | 이미지 업로드부터 저장까지의 사용 경험 피드백 | 수기 입력 대비 기록 부담 감소 여부 확인 |
| 목표 설정 및 활용 | 월별 목표 설정, AI 목표 제안 적용 여부 | 목표 관리 기능과 AI 제안의 활용성 평가 |
| AI 코칭 만족도 | 코칭 답변 만족도, 근거 표시가 신뢰에 도움이 되었는지 확인 | AI 코칭의 유용성과 신뢰성 평가 |
| 서비스 지속 사용 의향 | 테스트 후 재사용 의향 및 개선 의견 수집 | 서비스의 지속적인 소비 관리 지원 가능성 평가 |

### 6-4. 프로젝트 성공 기준

- 5명 이상의 실사용자가 이미지 업로드부터 거래 저장, 목표 설정 및 AI 코칭까지 핵심 흐름을 경험한다.
- 거래 인식 및 저장 과정에서 발생한 수정 항목과 오류 유형을 수집한다.
- AI 코칭의 만족도와 실질적인 도움 여부를 평가한다.
- 테스트 결과를 기반으로 서비스 개선 방향을 도출한다.
